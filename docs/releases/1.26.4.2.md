# sysm 1.26.4.2 — Q4 2026 Structured Notes Fix Release

This revision makes `notes create --from-markdown` finish reliably. A live canary on macOS 27.0 found two states in which it created the note but could not format it, leaving a half-formatted note behind.

## Fixes

- Structured notes no longer stall on Notes' first-run checklist prompt. The first time anything marks a checklist item as checked on a Mac, Notes asks "Would you like to enable automatic sorting of checked items?". The prompt took focus, so the command failed with "Notes lost keyboard focus before formatting completed". sysm now answers it with **Not Now**, which leaves the Notes setting unchanged. If Notes shows any other dialog, the command stops and reports the dialog's text.
- Structured notes work when Notes is closed or its main window is not open. After Notes relaunched and restored only separate note windows, it reported no selected note, and the command could not confirm its target. sysm now reopens the main Notes window through the Window menu and waits longer for Notes to launch. If the selection still cannot be confirmed, the command stops before it changes the note.

## Compatibility

- No command, option, or output format changes.
- The minimum macOS version remains 26.
- Two new error messages can appear: one quotes a Notes dialog that sysm did not answer, and one asks you to open the main Notes window.

## Validation

The changes passed debug and release builds and 822 unit tests on macOS 27. Four new unit tests cover the new error messages and the partial-note report. On macOS 27.0, a live canary created structured notes with correct title, heading, and subheading styles, native checklists, and checked items. It passed when Notes was not running, when Notes was already running, when no main window was open, and when the first-run prompt appeared.
